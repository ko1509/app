## SWELLとSEOの関係（先に結論）

**SWELLはSEOに有利です。ただし有利なのは「土台」の部分で、検索順位を決めるのは記事の中身です。**

SWELLがやってくれること（自分で作らなくていい部分）：
- **表示が速い**：ページの速さは検索順位の要素の1つ。SWELLは軽く作られていて、「高速化」の設定（キャッシュ・遅延読み込み）も付いている。
- **HTMLの構造が正しい**：見出し（h1〜h3）の使い方が正しく、Googleが内容を読み取りやすい。
- **構造化データ**：記事（Article）とパンくずの構造化データを自動で出す。
- **目次・パンくず・関連記事**：読む人が迷わず、サイト内をめぐってもらいやすい（滞在時間・内部リンク）。
- **更新日の表示**：このサイトは直前に何度も更新するので、検索結果やページに「更新日」が出るのは大きい。
- **スマホ表示**：スマホで読みやすい。Googleはスマホ版のページを基準に評価する。

SWELLだけではできないこと：
- **記事の中身**：検索した人の疑問（いつ・どこで・どうやって）に、どこよりも早く正確に答えること。順位はほぼここで決まる。
- **イベントの構造化データ**：SWELLが出すのは「記事」の情報だけ。打ち上げ日・状況（延期など）は、自作プラグイン `mirai-core` で Event として出す。両方出してもぶつからない。
- **更新の速さ**：延期が発表されたら30分以内に直す、という運用。

SWELLと一緒に**入れないほうがいいプラグイン**（機能がかぶって遅くなる・表示が崩れる）：All in One SEO、Yoast SEO、Autoptimize、Jetpack、各種キャッシュ系（サーバーのキャッシュとSWELLの設定で足りる）など。SEOの設定は SWELL 開発元がすすめる **SEO SIMPLE PACK** を使う。

## ステップ1　ドメインとサーバー（30分）

1. **サイト名とドメインを決める**（`plan/02-site-design.md` の本命は「ミライミニイク」）。ドメイン・X・Instagramの3つが取れるか、同時に確かめる。
2. レンタルサーバーの管理画面で、ドメインを追加する。
3. **無料SSL**をオンにする（URLが `https://` になる）。
4. サーバーの「WordPress簡単インストール」で WordPress を入れる。
   - ユーザー名は `admin` などの推測されやすいものを避ける。
   - 「キャッシュ自動削除」「データベース名」などはサーバーの初期値でよい。

> サーバーの種類（エックスサーバー・ConoHa WINGなど）によって画面の名前は少し違う。わからないところがあれば、サーバー名を教えてくれれば手順を合わせます。

## ステップ2　SWELLを入れる（15分）

1. SWELLの会員サイト（SWELLERS'）から、**親テーマ**と**子テーマ**をダウンロードする。
2. 管理画面 → 外観 → テーマ → 新規追加 → テーマのアップロード で、親テーマ → 子テーマの順に入れる。
3. **子テーマを有効化**する（カスタマイズは子テーマに入れると、SWELLを更新しても消えない）。
4. 管理画面 → SWELL設定 → アクティベート で、SWELLERS' に登録したメールアドレスで認証する（認証しないとアップデートが受け取れない）。

## ステップ3　初期設定（30分）

### SSHが使える場合（おすすめ・5分）
1. `site/dist/mirai-core.zip` と `site/setup-wpcli.sh` を、WordPressのフォルダ（`wp-config.php` がある場所）にアップロードする。
2. SSHで入り、そのフォルダで `bash setup-wpcli.sh` を実行する。
   - タイムゾーン、パーマリンク、カテゴリー4つ、固定ページ3つ（下書き）、プラグイン（SEO SIMPLE PACK・WP Multibyte Patch・Contact Form 7・Pochipp・mirai-core）が、まとめて設定される。
   - 何度実行しても、同じものが二重にできることはない。

### 手作業でやる場合
| 場所 | 設定 |
|---|---|
| 設定 → 一般 | タイムゾーン「東京」、日付の形式「Y年n月j日」 |
| 設定 → パーマリンク | カスタム構造に `/%category%/%postname%/` |
| 投稿 → カテゴリー | 「未分類」を「お知らせ」（スラッグ `news`）に変更。次の4つを追加：<br>ロケット打ち上げ（`launch`）／天体イベント（`sky`）／宇宙スポット（`spot`）／機材・持ち物（`gear`） |
| プラグイン → 新規追加 | SEO SIMPLE PACK、WP Multibyte Patch、Contact Form 7、Pochipp |
| プラグイン → 新規追加 → アップロード | `site/dist/mirai-core.zip` |
| 設定 → ディスカッション | 「新しい投稿へのコメントを許可」をオフ（スパム対策） |

> **パーマリンクは最初に決めて、あとで変えない。** 変えると、それまでのURLの評価がリセットされる。

## ステップ4　SWELLの設定（30分。まず最低限だけ）

外観 → カスタマイズ：
| 項目 | 設定 | 理由 |
|---|---|---|
| サイト全体設定 → 基本カラー | メインカラーを1色決める（夜空の紺など） | 冒頭ボックスの枠の色にも使われる |
| ヘッダー | ロゴ画像がなければ、サイト名の文字だけでよい | 後で作る |
| 投稿・固定ページ → タイトル | 「公開日」と**「更新日」を両方表示** | 直前更新が読む人に伝わる |
| 投稿・固定ページ → 目次 | 目次を表示、h3まで | 長いガイドで迷わない |
| 投稿・固定ページ → 記事下エリア | 関連記事を表示 | 内部リンク |
| PR表記（SWELLのバージョンによって置き場所が違う。見つからなければ記事の冒頭に「この記事には広告を含みます」と1行書く） | 広告リンクのある記事で表示する | ステマ規制への対応（2023年10月〜） |

SWELL設定（管理画面のメニュー）：
| 項目 | 設定 |
|---|---|
| 高速化 | 「キャッシュ機能」をオン、「遅延読み込み」をオン。サーバー側にもキャッシュ機能があれば、どちらか片方で足りる |
| 構造化データ | 初期値のまま（Articleが出る） |

SEO SIMPLE PACK：
| 項目 | 設定 |
|---|---|
| 一般設定 → 基本 | サイトの説明文（例：「ロケットの打ち上げや流星群を見に行く人のための、初めてでも動けるガイド」） |
| 一般設定 → Googleアナリティクス | GA4 の測定ID（`G-` から始まる） |
| 一般設定 → ウェブマスターツール | Search Console の確認コード（下のステップ5） |
| 一般設定 → noindex | 「タグアーカイブ」「日付アーカイブ」を noindex（中身の薄いページを検索に出さない） |

## ステップ5　Googleにつなぐ（20分）

1. **Search Console**：「URLプレフィックス」で `https://ドメイン/` を登録し、HTMLタグの確認コードを SEO SIMPLE PACK に貼る。
2. Search Console → サイトマップ に `wp-sitemap.xml` を送信する（WordPressが自動で作るもの）。
3. **GA4**：プロパティを作り、測定IDを SEO SIMPLE PACK に貼る。
4. X・Instagram のプロフィールにサイトのURLを入れる。

ここまでで、記事を公開できる状態になる。

## ステップ6　記事#1を書いて出す（10/17まで）

1. 投稿 → 新規追加。右上の「＋」→ パターン →「ミライミニイク」→ **「A 打ち上げ観覧ガイド」** を入れる。見出しがそろった下書きが入る。
2. 右側の「**イベント情報（ミライミニイク）**」欄を埋める：
   | 欄 | 記事#1の入力例 |
   |---|---|
   | イベント日 | 2026-10-20 |
   | 時刻 | 4:41 |
   | 今の状況 | 予定どおり |
   | 場所 | 種子島宇宙センター（鹿児島県南種子町） |
   | 公式情報のURL | `https://fanfun.jaxa.jp/countdown/mmx_h3f10/index.html`<br>`https://x.com/mmx_jaxa_jp` |
   | メモ | 中継は3:46ごろから。予備期間は10/21〜11/7 |
   | 最終確認日時 | 「最終確認を『いま』にする」ボタン |
   | Event の構造化データ | オン |
3. カテゴリー「ロケット打ち上げ」、URL（スラッグ）を `h3-f10-mmx` にする → `/launch/h3-f10-mmx/`。
4. 本文は AIプロンプトの型1・型2（管理アプリの「AI」タブ）で下書きし、**日時・場所・中継時刻は公式ページで目で確かめる**。
5. 公開したら、Search Console の「URL検査」→「インデックス登録をリクエスト」。
6. 管理アプリの記事ボードで #1 を「公開済み」にし、公開URLを入れる。

### 延期が発表されたとき（30分以内）
1. 投稿の「今の状況」を **延期** か **日程変更** にする（構造化データの eventStatus も自動で変わる）。
2. 新しい日が出たら「イベント日」を直す。
3. 「最終確認を『いま』にする」→ 更新。
4. 本文の「更新履歴」に1行足す → Xで告知（管理アプリの「SNS」タブ）。

投稿一覧に「イベント日（T−5 など）・状況・最終確認」の列が出るので、直前の記事を見落とさない。

## この手順で確かめたこと

- `mirai-core` は、WordPress 7.1.3（日本語版）＋PHP 8.3 の手元環境で次を確認した：
  - 有効化できる
  - 入力欄の保存と、不正な値の除去（`javascript:` のURL、HTMLタグ）
  - 冒頭ボックスの表示（記事にショートコードがあるときは二重に出ない）
  - Event の構造化データ
  - 投稿一覧の列
  - 3つのパターンが正しいブロックとして読み込まれること
- `setup-wpcli.sh` は同じ環境で2回実行し、二重に作られないことを確認した。
- **SWELLを入れた状態では試していない**（SWELLは有料テーマのため）。冒頭ボックスの見た目がSWELLのデザインとぶつかったら教えてください。
