# スマホ（iPhone Safari）でヘッダーと年表が揺れる件の対策

## 現在の状態（2026-10-25 夜）
- **進捗バーの対策（`mg-progress-calm.js`＋`.css`）が公開サイトに入っている**（フッター直前のウィジェット `custom_html-2`、`python3 deploy_widget.py apply`）。WAF（SiteGuard Lite）が `createElement` を含むスクリプトを止めるため、運営者が WAF を一時停止して反映した。**反映のあとは WAF を戻すこと。**
- 公開ページで確認（WebKit・iPhone 14 と PC）：記事ページで、ヘッダーの書き換え 0回・進捗バーはヘッダーの外・幅は元の計算と一致・エラーなし。ヒストリー・トップ・カテゴリでは何も起きない（エラーなし）。
- 外すには：`python3 deploy_widget.py remove`（使用停止中へ移す）。今後の更新も、`createElement` を含むので、WAF の除外か一時停止が要る。

## 経過（2026-10-25）
- 試した：①スクロール中の描画停止（`mg-scroll-calm.js`）、②スマホで星を出さない（`mg-no-stars-mobile.css`）。どちらも、運営者の iPhone では揺れが直らなかった（②の星は、運営者の指示で戻した）。①も、運営者の指示で外した。**いまサイトに入っている追加のコードは無い**（ウィジェット `custom_html-2` は「使用停止中」）。
- **次の有力な原因：ヘッダーの「中」の進捗バー（`.mg-prog`）。** スクロールのたびに、記事と全見出しの位置を測ってから、固定のヘッダーの中の要素を書き換えている。WebKit で、短いスクロールの間に、ヘッダーの中身が **5回** 書き換わることを確認（`MutationObserver`）。
- 対策案：`mg-progress-calm.js`＋`.css`（ヘッダーから外して、body 直下の固定要素にし、更新は1フレームに1回、位置は最初に測った値）。WebKit で、**ヘッダーの書き換え 5回 → 0回**、バーの値は元の計算と一致（0.0517／期待 0.052）、エラーなしを確認済み。
- **反映は、WAF に止められた**：REST でウィジェットに入れようとしたら 403（認証なしの確認用の送信でも 403＝WAF の規則）。止まる最小の並びは、`D.createElement('div')` を含む行（それより前までは通る）。**WAF の設定は運営者の判断**なので、回避していない。反映は、管理画面のカスタマイザー（引き継ぎメモの手順）で、`mg-progress-calm.css` を custom_css の最後に、`mg-progress-calm.js` を `<script>…</script>` で foot_code の最後に足す。
- 年表（ヒストリー）：`prog()` は、スクロールのたびに `getComputedStyle`・`scrollWidth`・全イベントの `offsetLeft` を読む。進捗バーの対策で直るか見てから、必要なら見直す。


2026-10-24 の引き継ぎメモ（別環境での作業）を受けて、ライブのサイト（https://miagetabi.space/history/）の実際の CSS・JS を読んで作った対策。
**この環境には WebKit（iOS）も WordPress の管理画面のログインも無いため、実機の確認と反映は行っていない。**

## 1. 対策1：スクロール中は描画を止める（`mg-scroll-calm.js`）
- 追加するもの：フッターコード（`loos_customizer[foot_code]`）の、既存の `<script>` の**あと**に、別の `<script>` として足す。既存のコードは変えない。
- 動き：タッチ端末（`pointer:coarse`）か幅700px未満のとき、スクロール中（止まって180msまで）は `requestAnimationFrame` のコールバックを次のフレームへ持ち越す。コールバックは捨てない。パソコンでは何もしない。
- ねらい：星の canvas・ロゴの点・`data-px`・ティッカーなど、毎フレームのメインスレッドの仕事をスクロール中だけ止める。iOS はメインスレッドが忙しいと sticky／fixed の要素が追いつかず揺れるため（引き継ぎメモの推定原因 1・4・5 に効く見込み）。
- 手元の確認（Chromium・スマホ相当の画面・ライブのヒストリーで1600pxをスクロール）：
  - スクロール中の canvas 描画の呼び出し：**7,735回 → 1,351回（約83%減）**。エラーなし。スクロール位置・見た目は同じ。
  - Chromium では、もともと長いタスクが出ない（性能の高い環境のため）。**iPhone で揺れが減るかは、実機でしか分からない。**
- 戻し方：足した `<script>` を消すだけ。

## 1-2. 対策1b：スマホでは背景の星を出さない（`mg-no-stars-mobile.css`）
- **WebKit での測定**（この環境に Playwright の WebKit を入れた。iPhone 14 の画面、公開中のサイト、スクロール1600px、3回の中央値。ソフトウェア描画なので、絶対値は iPhone と違う。相対比較にだけ使う）：

  | 条件 | ヒストリー（フレーム間隔の中央値／遅い5%） | 記事（同） |
  |---|---|---|
  | そのまま | 50ms／69ms | 34ms／46ms |
  | 対策1（描画の停止）だけ | 47ms／72ms | 33ms／46ms |
  | 対策1＋`#mg-stars` を非表示 | **25ms／46ms** | **20ms／31ms** |
  | 対策1＋`#mg-fx`（演出）を非表示 | 42ms／61ms | 27ms／36ms |
  | 対策1＋星を、スクロール中だけ非表示 | 47ms／64ms | 28ms／40ms（ほぼ効かない） |
  | 対策1＋星を CSS のグラデーションに置換 | 104ms／130ms（**悪化**） | 23ms／110ms（悪化） |
  | `will-change`・`translateZ`・`contain`・不透明度を1に・`overflow-x:clip` を外す・ヘッダーの合成化 | 効果なし（±数ms） | 効果なし |
- 読み取り：重いのは JS の描画ではなく、**全画面に固定した星の canvas を、スクロールのたびに合成し直すこと**。canvas のレイヤー化・小細工では軽くならず、**出さない**のが一番効く。スクロール中だけ隠す、CSS の星に置き換える、は効かない（悪化もある）。
- 代わりに失うもの：スマホの背景の星（デコレーション）。演出（`#mg-fx`）・ロゴ・ティッカーは残る。
- 実機の iPhone（GPU 合成）では、差はもっと小さいかもしれない。**対策1と1bを入れて、実機で揺れが減るかを見て、減ったら星を戻す（1bを消す）か、星を間引く方向を考える。**

## 2. ライブのコードを読んで分かったこと（原因の候補の絞り込み）
- `frame()`（星・流れ星・ロゴ）は常時 rAF で動く。スマホは33msに間引き済みだが、スクロール中も動いている → 対策1で止める。
- `punch()`（`punchRects`・`blockRects`）は、本文の全テキストノードと最大500要素の `getBoundingClientRect` を測る重い処理。`scroll` のたびに `prT=0` に戻して**毎フレーム測り直す**作りだが、動くのは「打ち上げの演出（`launches.length`）」の最中だけ。演出中にスクロールすると強く揺れる可能性がある。→ 対策2の候補。
- `#mg-stars,#mg-fx{position:fixed;inset:0;width:100vw;height:100vh}`：iOS の下部バーの出入りで `100vh` と見えている高さがずれる。JS は `100vh` のプローブで canvas の大きさを固定済みなので、揺れの主因ではなさそう。
- `#body_wrap{overflow-x:clip!important}`：iOS の古い版では sticky に影響する例がある。→ 対策3の候補（横スクロールが出ないか要確認）。
- `.l-header{position:sticky;top:var(--wp-admin--admin-bar--height,0px)}`、`.mz-htl__stick{position:sticky;top:var(--hdr)}`：ヘッダーの高さは小数2桁で保持済み。

## 3. 次に試す順番（対策1・1bで直らないとき）
1. **対策2**：`punch()` を、スクロール中は呼ばない（`W.addEventListener('scroll',function(){prT=0})` を、`prT=t` に変えて測り直しを間引く。または演出中は `moving` のとき `punch` を飛ばす）。
2. **対策3**：スマホだけ `#body_wrap{overflow-x:visible!important}` にして、`html{overflow-x:hidden}` で横のはみ出しを抑える。**ページが横に動かないか**を確かめてから。
3. **対策4**：ヘッダーをスマホだけ `position:fixed` にして、同じ高さのスペーサーを入れる。
4. **対策5**：ヒストリーのスマホ版は、固定ステージをやめて、ネイティブの横スクロール（`is-static`）にする。

## 4. 実機で切り分けてほしいこと（iPhone）
- 場所：ヒストリーか記事か ／ タイミング：指で動かしている間か、止まる直前か ／ 揺れるもの：ヘッダーだけか、年表も ／ 通常ブラウズとプライベートブラウズの違い。
- 対策1を入れたあとの変化（「少し減った」「変わらない」「年表だけ残る」など）。

## 5. 反映のしかた（引き継ぎメモの手順）
管理画面のカスタマイザーを開いたタブで、(1) `mg-scroll-calm.js` を `<script>…</script>` で包んだものを、`wp.customize('loos_customizer[foot_code]')` の値の**最後**に足す。(2) `mg-no-stars-mobile.css` の中身を、`wp.customize('custom_css[swell_child]')` の値の**最後**に足す。そのあと `wp.customize.previewer.save()`。SiteGuard Lite（WAF）はオンのまま。設定は変えない。
