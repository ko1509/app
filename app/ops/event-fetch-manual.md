# イベント取得エージェント（eventfetch）の手順書

公式の予定表と天体の暦から、**まだアプリのイベントに無い**打ち上げ・天体イベント・宇宙スポットの催しを見つけ、イベントに足す。既にあるイベントの変更（延期など）は公式ウォッチの仕事。

**書き換えてよいもの**：新しい `events/<ID>` の作成（`set`）だけ、受信箱 `inbox/…`、自分の `jobs/<ID>`
**書き換えないもの**：既にある `events`（日時・状況を含む）、`articles`、ほかのエージェントの持ち物

## 0. 共通
`ops/agent-jobs.md`（共通の約束。停止の確認を含む）と `ops/site-rules.md`（とくに 2「扱うこと・扱わないこと」）を読んでから進める。

## 1. いつ動くか
- 定時：月曜と木曜の朝（6時台）。
- 依頼：`kind: "eventfetch"`（運営者がアプリで「今すぐ動かす」を押したとき）。

## 2. 見る場所（実際に開く。上から順に）
| 題材 | 見る場所 |
|---|---|
| JAXA の打ち上げ | https://www.jaxa.jp/press/ （打ち上げ予定日のお知らせ）、https://fanfun.jaxa.jp/countdown/ |
| カイロス（スペースワン） | https://www.space-one.co.jp/ のお知らせ |
| ZERO・MOMO（インターステラテクノロジズ） | https://www.istellartech.com/ のお知らせ |
| 天体イベント | 国立天文台 ほしぞら情報（今月・来月・再来月）https://www.nao.ac.jp/astro/sky/ 、暦計算室 https://eco.mtk.nao.ac.jp/koyomi/ |
| 流星群 | IMO の流星群カレンダー https://www.imo.net/resources/calendar/ （日時は世界時。`sky.py ut2jst` で日本時間に直す） |
| 宇宙スポットの催し | JAXA の施設の特別公開・イベント（https://fanfun.jaxa.jp/event/ ） |

まとめサイト・個人ブログ・SNS は根拠にしない（手がかりにはしてよい）。

## 3. 手順
1. 共通の手順で依頼を受け取る（定時なら `jobs/eventfetch-<YYYYMMDDHHMM>` を自分で作ってから進めてよい）。
2. `events` を全部読む（重複を避けるため）。
3. 2 章の場所を開き、**今日から6か月以内**（打ち上げは日付未発表でも、年度内の予定として公式に出ているもの）を候補にする。扱わない話題（ビジネス・投資・エネルギー・原子力など）は除く。日本から見えない天体現象（日本で見えない日食・半影月食で見え方がわずかなもの）は、国立天文台の記述で確かめて除く。
4. **重複を除く**：同じ機体・号機、同じ天体現象（同じ流星群の同じ年）、同じ催しが `events` にあれば足さない。名前が違っても中身が同じなら足さない。
5. 足すもの（1回に10件まで）を `events/<pillar>-<YYYYMMDD>-<短い英字>` で `set`：
   ```json
   {"title": "H3ロケット11号機（HTV-X2）", "pillar": "launch|sky|spot",
    "date": "YYYY-MM-DD（未発表なら空）", "time": "4:41（未発表なら空）", "dateText": "日付が未発表のときの公式の表記（例：2026年度）",
    "place": "種子島宇宙センター", "status": "確定（公式に日時が出ている）|予定（公式の予定・時期だけ）",
    "source": "確かめた公式ページの URL", "note": "1行（何を確かめたか）",
    "by": "eventfetch", "addedAt": "<今>", "checkedAt": "<今>"}
   ```
   - 時刻は日本時間。曜日・世界時の変換は `sky.py` で。
   - 打ち上げで「時刻は後日発表」なら `time` は空。
   - 天体イベントの `date` は見ごろの日（極大が夜をまたぐときは、夜の始まりの日）。`note` に「21日の夜〜22日の明け方」のように書く。
6. 迷うもの（公式の記述があいまい、扱うか判断がつかない）は足さずに、受信箱に `kind: "other"` で1件にまとめて出す（根拠の URL つき）。
7. 依頼を `done` にし、報告する（3行以内：足した件数と主なもの）。

## 4. してはいけないこと
- 既にあるイベントを書き換えること（変化に気づいたら報告に書く。直すのは公式ウォッチ）。
- 推測で日付を作ること。「例年○日ごろ」で日付を入れること。
- 記事カードを作ること（記事にするかは企画と運営者が決める）。
