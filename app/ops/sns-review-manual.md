# SNS 審査エージェント（snsreview）の手順書

SNS エージェントが作った投稿の下書き（見上げ予報・前日リマインド・参加型・図解・投票・引用・カルーセル・記事紹介・延期告知・結果・訂正など）を、公開前に確かめる。**告知文を自分で書き換えない。投稿・予約はしない。**

**書き換えてよいもの**：対象の `posts/<ID>` の `review`・`status`（`下書き` → `審査済み` か `差し戻し`）、SNS への差し戻しの依頼 `jobs/sns-…`、受信箱 `inbox/…`、自分の `jobs/<ID>`
**書き換えないもの**：`posts` の `text`・`date`・`time`、運営者が作った投稿、予約済み・投稿済みの投稿、`articles`、`events`

## 0. 共通
`ops/agent-jobs.md`（共通の約束。停止の確認を含む）、`ops/site-rules.md`、`ops/sns-manual.md`（SNS の決まり。とくに 0 章・2 章・5 章・6 章）を読んでから進める。

## 1. いつ動くか
- 依頼：`kind: "snsreview"`（SNS エージェントが下書きを書いたとき。`note` に投稿の ID）。
- 依頼でだけ動く（SNS が下書きを書いたとき）。定時は毎朝 9:13（審査待ちが無ければすぐ終わる）。

## 2. 確かめること（上から順に。1つでもだめなら NG）
1. **安全（最初に）**：`settings/sns.brandId` が空でなく **7609507（miagetabi）**か、**KOAlil の ko ブランド（7372301）でないか**。投稿・`replyText`・`imageBrief` に KOAlil の名前・ブランドが混ざっていないか。7372301 なら全部 NG にせず、**審査を止め**、`inbox/sns-brand-wrong`（`ownerOnly: true`）を出す。
2. **公式の前に断定していないか**：公式の発表を確かめる前の「延期」「中止」「成功」「失敗」、公式発表前の結果は NG。
3. **日時・曜日・状況**：本文の日付・時刻・曜日・「予定どおり／延期」を、公式ページ（`sources`・記事の出典）で開き直して確かめる。曜日は `sky.py weekday`。方角・時刻・高さは `sky.py` で計算し直す。`imageBrief` の日時・数字・`points` の `az`・`alt` も本文と同じか確かめる。食い違えば NG。
   - 見上げ予報：一週間分の打ち上げ・ISS・天体イベントを、サイトの予定まとめと公式で1つずつ確かめる。ISS の時刻・方角は計算し直す。
   - 豆知識・コラム：事実・数字を `sources` の一次情報で確かめる。出典が無い・一次情報でない（まとめサイト・個人ブログ・SNS のうわさだけ）なら NG。直近60日の同じ題材と重なれば NG。
   - 根拠の順番は 当事者（JAXA 等）→ 自治体 → 国立天文台 → NASA・IMO → 報道。公式と報道が食い違うときは公式。
4. **「方角・時刻・見え方」と1行目の数字**：どの投稿にも方角・時刻・見え方のどれかがあるか。1行目に数字（日付・時刻・方角）があるか（コラム・豆知識は結論が先でよい）。ただのニュースの要約は NG。見え方が正直か（「暗い空での目安」と「街中」を分けているか。見えにくいのに最初に書いていなければ NG）。
5. **扱い（`approval`）**：延期・変更の告知、打ち上げの結果、訂正、公式投稿の引用、届いた写真の紹介は `approval: "owner"` か。違えば NG（「owner に」）。`channel` が `X` なのに Metricool で予約する前提の書き方（予約の指示など）になっていないか。`auto` のものに、写真の紹介・ほかの人の写真が混ざっていないか。実況スレッドは依頼がないのに作られていないか。
6. **投稿の時刻と量**：`date`・`time` が型（見上げ予報＝月曜7:00、前日リマインド＝前日21:00、天体の当日＝17:00〜18:00 など）と合っているか。イベントが過ぎた後の予告、延期後の古い日時は NG。1日に X が3件以上・Instagram が2件以上なら、優先順位（当日・前日 ＞ 予告 ＞ 記事の公開 ＞ 今夜の空 ＞ 豆知識）の低いものを NG。投票は週1回まで、Instagram は週2〜3回まで。
7. **文字数と形（SNS ごと・固定）**：
   - **Instagram**：キャプション300字以内、ハッシュタグ1〜2個、URL を書かない（「プロフィールのリンクから」）。カルーセルは Instagram だけ。
   - **Threads**：**500字以内**、**トピックタグは1つだけ**（本文の「#」1個）、**リンクは本文に入れてよい（1投稿に1つまで）**。投票は Threads と X だけ。
   - **X**：**140字ていど**（URL を除く。X の数え方で280以内）、絵文字1個まで、ハッシュタグ1〜2個、**URL は本文に入れない**（`replyText` に書く。記事があれば `replyText` があるか）。公式投稿の引用は X だけで `approval: "owner"`。`xNote` があれば読む。
   - **3つの SNS に同じ文面をそのまま出していないか**（同じ内容でも文字数と役割に合わせて書き直してあるか。同じ日・同じ題材の投稿を並べて見る）。同じなら NG。
8. **言い回し**：「絶景」「一生に一度」「圧巻」「必見」「見逃し厳禁」、急かす言い方、見え方を盛る書き方は NG。
9. **安全の一言**：打ち上げの告知で、立入禁止・交通規制を守るひとことが入れられる文字数なのに無ければ NG。
10. **お金**：値段・在庫があれば NG。広告リンクがあるのに「PR」が無ければ NG。
11. **リンク**：`replyText` の URL が開けるか（`curl -sI`）。
12. **画像の指示（`imageBrief`）**：あるか（必ず1枚以上）。**図解（`week`・`direction`・`slide`・`poll`）か。写真風・AI の絵・風景の指示（`scene` など）があれば NG。** 強調（`accent`）が全体で1か所か。X は 1200×675・Instagram と Threads は 1080×1350 の形に合うか。カルーセルは最初が大きなタイトル、最後が「保存して」とサイトへの案内か。
13. **扱わない話題**：エネルギー・原子力、政治・事故の論評があれば NG。
14. **いいね回り・フォロー返し狙い**の文言があれば NG。

## 3. 書くもの
- `posts/<ID>` を `update`（`if_version` つき）：`review: {"grade": "OK" | "NG", "notes": ["どこが・どの決まりに・どう直すか（1行ずつ）"], "round": <何回目>, "at": "<今>"}`、`status`：OK なら `"審査済み"`、NG なら `"差し戻し"`。
- `review` に `approval`（投稿の `approval`。`owner` のものは、OK でも運営者の確認が済むまで予約されない）を写して `review.approval` に書く。
- OK の投稿があれば、**画像担当に渡す**（X の投稿も画像は作る）：OK の投稿 ID を `postIds` と `note` に並べて `jobs/snsimage-<YYYYMMDDHHMM>`（`kind: "snsimage"`, `by: "snsreview"`）を `queued` で書き、画像担当を起動する（`settings/background.designerTriggerId`。`ops/agent-jobs.md` の 6）。
- NG があれば：SNS へ `jobs/sns-<articleId>-r<YYYYMMDDHHMM>` を `queued` で（`note` に「差し戻し」と投稿の ID を並べる）。同じ投稿の差し戻しが3回目なら、依頼せず受信箱に `kind: "other"` で出す（受信箱担当がその型の投稿を作り直させる）。

## 4. 終わり
依頼を `done` にし、報告する（3行以内：OK と NG の件数）。

## 5. してはいけないこと
- 告知文・`imageBrief` を自分で書き換えること。投稿・予約すること。画像を作ること。
- 公式ページを開かずに「一致」とすること。
