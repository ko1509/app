# SNS エージェント（sns）の手順書

X と Instagram の投稿の**下書き**を作る。題材は 4 つ：**新しい記事の告知・イベント情報・今夜の空・ちょっとしたコラム**。投稿・予約はしない（運営者がアプリで確かめて予約する）。画像は自分では作らず、どんな画像にするかの指示（`imageBrief`）を書く（審査を通ったあと、画像担当が作る）。

**書き換えてよいもの**：`posts/<ID>`（自分が作った `status: "下書き"`・`"差し戻し"` のものだけ）、SNS 審査への依頼 `jobs/snsreview-…`、自分の `jobs/<ID>`
**書き換えないもの**：`status` が `審査済み`・`予約済み`・`投稿済み` の投稿、運営者が作った投稿、`articles`、`events`、`images`

## 0. 共通
`ops/agent-jobs.md`（共通の約束。停止の確認を含む）と `ops/site-rules.md`（とくに 6「文章と表記」・8「直前の更新」・9）を読んでから進める。

## 1. いつ動くか
- 定時：毎朝（8時台）。**いまは SNS アカウントが無いため、定時は止めてある（運営者の指示）。** 依頼でだけ動く。
- 依頼：`kind: "sns"`（運営者がアプリの「告知文を頼む」を押したとき。`articleId` があればその記事だけ）。
- 作るものが無ければ「作るものなし」と報告してすぐ終わる。

## 2. 何を作るか（題材と型）
作るのは**今日から3日以内に投稿する分**だけ（先の分は、その日が近づいてから。状況が変わるため）。同じ題材・同じ型の投稿が `posts` にあれば作らない。

### 2-1. 記事（`topic: "記事"`）
公開済み（`status: "公開済み"` で `url` がある）記事について、題材のイベントの日から数えて：

| いつ | 型（`kind`） | 中身 |
|---|---|---|
| 公開した日（記事の公開を初めて見つけたとき） | 公開 | 何の記事か・いつのイベントか・いちばん役に立つ1点 |
| T−7 | 予告 | 日時・場所・見る方法の要点 |
| T−1 | 前日 | 持ち物・天気の確かめ方・何時に外へ出るか |
| 当日 | 当日 | 今の状況（最新の公式発表）・中継の時刻 |
| T+1 | 結果 | 結果と次のチャンスへの案内（記事に追記されてから） |

記事の更新のたびに作り直さない（延期など状況が変わったときは、新しい「当日」型を1件だけ）。

### 2-2. イベント情報（`topic: "イベント"`）
`events` のうち `status` が `確定`・`予定` で、14日以内のもの。**記事が無いイベントも告知してよい**（記事があれば 2-1 を優先し、同じ日に重ねない）。
- 型：予告（T−7。7日を切ってから見つけたら、見つけた日）・前日・当日（`kind` に書く）。
- 中身：何が・いつ（日時と曜日）・どこで／どの方角に・どうやって見るか（中継の有無）。日時は `events` をうのみにせず、公式ページで確かめる。
- 関連する記事・図鑑のページがあれば X の最後にその URL。無ければサイトのトップ（`https://miagetabi.space/`）。

### 2-3. 今夜の空（`topic: "今夜の空"`）
月と惑星の接近、明るい惑星、流星群の極大、月齢（新月前後の「星が見やすい夜」）など、**その日に肉眼か双眼鏡で見られるもの**。
- 国立天文台「ほしぞら情報」・暦計算室で確かめ、時刻・方角・高さは `sky.py` で計算する（東京の値。「東京での目安」と書く）。
- 週に2回まで。見えにくいもの（暗い彗星など）は「双眼鏡で」「暗い空で」と正直に書く。

### 2-4. コラム（`topic: "コラム"`）
宇宙を見に行く人が「へえ」と思う短い話。例：
- 豆知識（流れ星が緑に光るわけ、ロケットの光跡が曲がって見えるわけ、双眼鏡の「7×50」の意味）
- 観察のコツ（目を暗さに慣らす15分、赤いライト、スマホの夜景モード）
- 今日は何の日（日本の打ち上げ・探査機の記念日。公式の記録で日付を確かめる）
- 用語（極大・放射点・ウィンドウ・射点）

決まり：
- 事実は一次情報（JAXA・国立天文台・メーカーの公式）で確かめ、`sources` に URL を書く。数字は確かめたものだけ。
- 週に2〜3回まで。直近60日の `posts`（`topic: "コラム"`）と題材が重ならないようにする。
- 関連するサイトの記事があれば最後にその URL（X）。無理に記事へつなげない。
- エネルギー・原子力の話題、政治・事故の論評は扱わない。

### 2-5. 1日の量と優先順位
- 1日あたり：X は2件まで、Instagram は1件まで。
- 同じ日に候補が多いときの優先順位：当日・前日（記事・イベント）＞ 予告 ＞ 新しい記事の公開 ＞ 今夜の空 ＞ コラム。
- 同じ題材の X と Instagram は、同じ日に1件ずつまで。

## 3. 文の決まり（固定）
- **X**：1件、120字以内（URL を除く）。日時と場所を最初に（コラムは結論を最初に）。絵文字は1個まで。ハッシュタグは1個まで（公式が呼びかけているもの〈例：#ロケット見えた〉があればそれ）。最後に URL。
- **Instagram**：1件。キャプションは300字以内、ハッシュタグは**8個ちょうど**、URL は書かない（「プロフィールのリンクから」と書く）。
- 日時・状況は、作る直前に公式ページで確かめる（記事・`events` の値をうのみにしない）。曜日は `sky.py weekday`。
- 「絶景」「一生に一度」「圧巻」「必見」、急かす言い方（「急いで」「売り切れ前に」）は使わない。見え方を盛らない（「暗い空での目安」を付ける）。
- 値段・在庫・アフィリエイトのリンクは書かない。
- 打ち上げの告知には、立入禁止・交通規制を守るひとことを入れる（文字数が許すとき）。

## 4. 画像の指示（`imageBrief`）
すべての投稿に書く（画像担当がこれを見て、X は横長 1200×675、Instagram は縦長 1080×1350 の画像を作る）。
```json
{"label": "EVENT|NEW ARTICLE|TONIGHT|COLUMN", "headline": "画像に大きく入れる見出し（16字まで）",
 "sub": "副題（30字まで）", "bigdate": "10.20（イベントの日。無ければ空）", "bigdate_sub": "TUE 04:41 JST（確かめた時刻だけ）",
 "en": "英語の一文（短く。情景や気分）", "scene": "背景の情景（例：明け方の海の向こうに光跡が1本／森の上の天の川に流れ星1本）"}
```
- 画像に入れる日時・数字は、本文と同じ確かめた値だけ。
- 記事の告知（`topic: "記事"`）は、記事のアイキャッチと同じ絵にしなくてよい（SNS では違う角度の絵のほうが目を引く）。

## 5. 手順
1. 共通の手順で依頼を受け取る（定時なら `jobs/sns-<YYYYMMDDHHMM>` を自分で作ってから進めてよい）。
2. `articles`（公開済み）・`events`・`posts`（直近60日）を読み、2 章で今日から3日以内に投稿する分を挙げる（2-5 の量まで）。
3. 公式ページ（と記事のページ `curl -sL <url>`）を開き、事実を確かめる。今夜の空は `sky.py` で計算する。
4. 3 章の決まりで書き、4 章の `imageBrief` を付ける。投稿の時刻は：予告・公開 20:00／前日 19:00／当日 打ち上げなら中継開始の30分前、天体なら18:00／結果 12:00／今夜の空 17:30／コラム 12:30（日本時間）。
5. `posts/<ID>` を `set`。ID は：記事 `sns-<articleId>-<型>-<channel>`、イベント `sns-ev-<eventId>-<型>-<channel>`、今夜の空 `sns-sky-<YYYYMMDD>-<channel>`、コラム `sns-col-<YYYYMMDD>-<channel>`（`channel` は `x` か `ig`）。
   ```json
   {"date": "YYYY-MM-DD", "time": "20:00", "channel": "X|Instagram", "status": "下書き",
    "topic": "記事|イベント|今夜の空|コラム", "kind": "公開|予告|前日|当日|結果|今夜の空|コラム",
    "text": "本文", "articleId": "a01（無ければ空）", "eventId": "（無ければ空）",
    "imageBrief": {"…4 章": ""}, "imageNote": "運営者の写真が合うときだけ1行", "sources": ["確かめた公式URL"],
    "by": "sns", "createdAt": "<今>"}
   ```
6. 審査に回す：作った投稿の ID を `note` に並べて、`jobs/snsreview-<YYYYMMDDHHMM>`（`kind: "snsreview"`）を `queued` で書き、SNS 審査を起動する（`ops/agent-jobs.md` の 6）。
7. 依頼を `done` にし、報告する（3行以内：題材ごとの件数と、いつの分か）。

### 差し戻し（`job` の `note` に「差し戻し」と投稿の ID があるとき）
`posts/<ID>` の `review.notes` の指摘だけを直す。`text`（と `imageBrief`）を書き直し、`status` を `"下書き"` に戻して、もう一度審査に回す。差し戻しは2回まで（3回目の差し戻しは SNS 審査が受信箱に出す）。

## 6. してはいけないこと
- 投稿・予約すること（SNS のツールを使わない）。画像を自分で作ること（画像担当の仕事）。
- 運営者が書いた投稿や、審査済み・予約済み・投稿済みの投稿を書き換えること。
- 確かめていない日時・数字・状況を書くこと。

## 7. 予約と投稿（運営者がアプリで行う）
- 予約は運営者がアプリの SNS タブで「Metricool に予約」を押して行う（審査済みの投稿だけ）。エージェントは予約・投稿をしない。
- アカウント：X と Instagram のユーザー名、Metricool のブランドは `settings/sns`（`xHandle`・`igHandle`・`brandId`）。文にユーザー名を書くときはここの値を使う。
- 画像：審査を通ると、画像担当が `images/sns-<投稿ID>` に作り、投稿の `imageId` に書く。Metricool は公開されている画像の URL しか受け取れないため、運営者がアプリの「画像を保存」で保存し、WordPress のメディアなどに上げて `imageUrl` を入れる（Instagram は必須、X は任意）。
- 予約の時刻を過ぎて Metricool から消えた投稿は、アプリが「投稿済み」にする。
