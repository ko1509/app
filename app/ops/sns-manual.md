# SNS エージェント（sns）の手順書

公開済みの記事とイベントの予定から、X と Instagram の告知文の**下書き**を作る。投稿・予約はしない（運営者がアプリで確かめて、自分で投稿・予約する）。

**書き換えてよいもの**：`posts/<ID>`（自分が作った `status: "下書き"` のものだけ）、自分の `jobs/<ID>`
**書き換えないもの**：`status` が `予約済み`・`投稿済み` の投稿、運営者が作った投稿、`articles`、`events`

## 0. 共通
`ops/agent-jobs.md`（共通の約束。停止の確認を含む）と `ops/site-rules.md`（とくに 6「文章と表記」・8「直前の更新」・9）を読んでから進める。

## 1. いつ動くか
- 定時：毎朝（8時台）。**いまは SNS アカウントが無いため、定時は止めてある（運営者の指示）。** 依頼でだけ動く。
- 依頼：`kind: "sns"`（運営者がアプリの「告知文を作る」を押したとき。`articleId` があればその記事だけ）。
- 作るものが無ければ「作るものなし」と報告してすぐ終わる。

## 2. いつの告知を作るか（告知の型）
公開済み（`status: "公開済み"` で `url` がある）記事について、題材のイベントの日から数えて：

| いつ | 型 | 中身 |
|---|---|---|
| 公開した日（記事の公開を初めて見つけたとき） | 公開 | 何の記事か・いつのイベントか・いちばん役に立つ1点 |
| T−7 | 予告 | 日時・場所・見る方法の要点 |
| T−1 | 前日 | 持ち物・天気の確かめ方・何時に外へ出るか |
| 当日 | 当日 | 今の状況（最新の公式発表）・中継の時刻 |
| T+1 | 結果 | 結果と次のチャンスへの案内（記事に追記されてから） |

- 作るのは、**今日から3日以内に投稿する分**だけ（先の分は、その日が近づいてから作る。状況が変わるため）。
- 同じ記事・同じ型の投稿が `posts` にあれば作らない。
- 記事の更新のたびに告知を作り直さない（延期など状況が変わったときは、新しい「当日」型を1件だけ）。

## 3. 文の決まり（固定）
- **X**：1件、120字以内（URL を除く）。日時と場所を最初に。絵文字は1個まで。ハッシュタグは1個まで（公式が呼びかけているもの〈例：#ロケット見えた〉があればそれ）。最後に記事の URL。
- **Instagram**：1件。キャプションは300字以内、ハッシュタグは**8個ちょうど**、URL は書かない（「プロフィールのリンクから」と書く）。画像は作らない・選ばない（`imageNote` に、運営者が撮った写真か図のどれが合うかを1行）。
- 日時・状況は、作る直前に公式ページで確かめる（記事の値をうのみにしない）。曜日は `sky.py weekday`。
- 「絶景」「一生に一度」「圧巻」「必見」、急かす言い方（「急いで」「売り切れ前に」）は使わない。見え方を盛らない（「暗い空での目安」を付ける）。
- 値段・在庫・アフィリエイトのリンクは書かない。
- 打ち上げの告知には、立入禁止・交通規制を守るひとことを入れる（文字数が許すとき）。

## 4. 手順
1. 共通の手順で依頼を受け取る（定時なら `jobs/sns-<YYYYMMDDHHMM>` を自分で作ってから進めてよい）。
2. `articles`（公開済み）・`events`・`posts` を読み、2 章の表で、今日から3日以内に投稿する分を挙げる。
3. 記事のページ（`curl -sL <url>`）と公式ページを開き、事実を確かめる。
4. 3 章の決まりで書く。投稿の時刻は、型ごとに：予告・公開 20:00／前日 19:00／当日 打ち上げなら中継開始の30分前、天体なら18:00／結果 12:00（日本時間）。
5. `posts/sns-<articleId>-<型>-<channel>` を `set`：
   ```json
   {"date": "YYYY-MM-DD", "time": "20:00", "channel": "X|Instagram", "status": "下書き",
    "text": "本文", "articleId": "a01", "eventId": "", "kind": "公開|予告|前日|当日|結果",
    "imageNote": "（Instagram のとき）", "sources": ["確かめた公式URL"], "by": "sns", "createdAt": "<今>"}
   ```
6. 審査に回す：作った投稿の ID を `note` に並べて、`jobs/snsreview-<articleId>-<YYYYMMDDHHMM>`（`kind: "snsreview"`）を `queued` で書き、SNS 審査を起動する（`ops/agent-jobs.md` の 6）。
7. 依頼を `done` にし、報告する（3行以内：作った件数と、いつの分か）。

### 差し戻し（`job` の `note` に「差し戻し」と投稿の ID があるとき）
`posts/<ID>` の `review.notes` の指摘だけを直す。`text` を書き直し、`status` を `"下書き"` に戻して、もう一度審査に回す。差し戻しは2回まで（3回目の差し戻しは SNS 審査が受信箱に出す）。

## 5. してはいけないこと
- 投稿・予約すること（SNS のツールを使わない）。
- 運営者が書いた投稿や、予約済み・投稿済みの投稿を書き換えること。
- 確かめていない日時・状況を書くこと。画像を作ること。

## 6. 予約と投稿（運営者がアプリで行う）
- 予約は運営者がアプリの SNS タブで「Metricool に予約」を押して行う（審査済みの投稿だけ）。エージェントは予約・投稿をしない。
- アカウント：X と Instagram のユーザー名、Metricool のブランドは `settings/sns`（`xHandle`・`igHandle`・`brandId`）。告知文にユーザー名を書くときはここの値を使う。
- Instagram は画像が無いと予約できない。`imageNote` に、運営者が撮った写真・使ってよい公式の画像・サイトの図のどれが合うかを具体的に書く（例：「記事の FIG.01 タイムライン図」）。画像の URL（`imageUrl`）は運営者が入れる。
- 予約の時刻を過ぎて Metricool から消えた投稿は、アプリが「投稿済み」にする。
