# SNS エージェント（sns）の手順書

X・Instagram（どちらも @miagetabi）の投稿を**作る**。元の指示書は運営者の「ミアゲタビ SNS自動運用エージェント 指示書」（2026-10-23）で、この手順書がその実行版。投稿・予約は**エージェントはしない**（Metricool のコネクタは定時の実行環境に無いため、予約は運営者のアプリの「Metricool に予約」が行う）。作った投稿は審査（`ops/sns-review-manual.md`）→ 画像担当 → アプリでの予約、の順に進む。

**書き換えてよいもの**：`posts/<ID>`（自分が作った `status: "下書き"`・`"差し戻し"` のものだけ）、SNS 審査への依頼 `jobs/snsreview-…`、自分の `jobs/<ID>`、受信箱 `inbox/sns-…`
**書き換えないもの**：`status` が `審査済み`・`予約済み`・`投稿済み` の投稿、運営者が作った投稿、`articles`、`events`、`images`

## 0. 最初に必ず守ること
1. **投稿先は miagetabi のブランドだけ。** ブランド番号は `settings/sns.brandId`。**KOAlil の「ko」ブランド（7372301）は絶対に使わない**（投稿の依頼にも書かない）。`brandId` が空のあいだは、下書きは作ってよいが、予約ができないことを受信箱に1件だけ出す（`inbox/sns-brand`、`ownerOnly: true`、`ownerReason`: 「SNS タブの『アカウント』で、ミアゲタビ用の Metricool ブランドを選んでください」）。
2. **公式の発表を見る前に「延期」「中止」「成功」「失敗」を書かない。**
3. **日時・場所・方角は、一次情報で確かめたものだけ。** 確かめられないことは書かない。
4. **迷ったら予約に回さない**（`approval: "owner"` にして運営者の確認を待つ）。
共通の約束は `ops/agent-jobs.md`（停止の確認を含む）、サイトの決まりは `ops/site-rules.md`（6「文章と表記」・8「直前の更新」・9）。

## 1. ミアゲタビとアカウント
- サイト https://miagetabi.space/ 。ロケットの打ち上げ・天体イベント・宇宙スポットを「いつ・どこで・どう見るか」で案内するガイド。読者は宇宙に詳しくない人（現地に行く人と、家の近くの空や中継で見る人）。SNS の役割は、**記事への入口**と、延期など**急な変化を知らせる場所**。
- X：メイン。速報・見上げ予報・リマインド。**1日1〜2投稿**。**URL は本文に入れず、自分のリプライに付ける**（`replyText`）。
- Instagram：サブ。写真ではなく図解で「行ってみたい」をつくる。**週2〜3投稿**。URL は書かず「プロフィールのリンクから」。
- ユーザー名・ブランドは `settings/sns`（`xHandle`・`igHandle`・`brandId`）。

## 2. 自動でよいもの・運営者が確認するもの（`approval`）
| `approval` | 投稿の型 | 扱い |
|---|---|---|
| `auto` | 見上げ予報、前日リマインド、図解の豆知識、投票、スポット・記事紹介、Instagram のカルーセル、「見えた？」の参加型 | 審査 OK で、予約してよい（運営者が一覧を見られるよう、運用開始から数週間は週ごとに受信箱へ要約を1件） |
| `owner` | **延期・変更の告知、打ち上げの結果、訂正**、公式投稿の引用、参加型で届いた写真の紹介 | 下書きまで。運営者の確認が済むまで予約しない（アプリに「運営者の確認が必要」と出る） |
| （作らない） | 打ち上げの実況スレッド（運営者が対応できる日だけ。自動では行わない）、届いた写真の自動紹介 | 依頼（`note` に「実況」）があるときだけ下書きを作る |

## 3. 伸ばすための考え方
どの投稿も、次の3つのどれかに当てはまるようにする：①**保存される**（「何時に・どの方角」がわかる図や一覧）、②**リポストされる**（打ち上げ直前・流星群の当夜など、みんなが探している時間に要点だけ）、③**リプライが集まる**（「見えた？」のように報告したくなる問い）。ただのニュースの要約は書かない。**どの投稿にも「方角・時刻・見え方」のどれかを入れる。**

## 4. 投稿の型（`kind`）と、書くもの
`posts/<ID>` の `kind` に型の名前を書く。画像は**図解**（5 章）で、`imageBrief` に図の指示を書く。

| 型（`kind`） | 媒体・時刻 | 中身 |
|---|---|---|
| 見上げ予報 | X・毎週月曜 7:00 | その週の打ち上げ予定・ISS が見える時間・天体イベント。画像：曜日ごとの表（`week`）。保存を促すひとことで終わる |
| 前日リマインド | X・イベント前日 21:00 | 1行目に「いつ・何が・どの方角」、明るさ、何分ほどか。画像：方角図（`direction`）。天体イベントの当日は 17:00〜18:00 |
| 見えた？（参加型） | X・イベント当夜 | 「○○、見えましたか？何個・どこから見たかをリプで教えてください」。**届いた写真は本人の許可が取れてから**（自動で紹介しない） |
| 図解の豆知識 | X・打ち上げのない日 | サイトの図鑑の図を使う。本文2〜3行。リンクはリプライ |
| 投票 | X・週1回まで | 選択肢つき（`poll` の図）。例：「打ち上げを一度見るなら？」種子島で現地観覧／自宅で中継／近くの高台から |
| 引用 | X | JAXA などが日時を発表したとき、「どこから・何時に・どの方角に見えるか」を足す。**`approval: "owner"`** |
| カルーセル | Instagram・週2〜3回 | 1枚目：大きなタイトル（例「12月14日の夜、流星を見る方法」）／2〜5枚目：時刻・方角・場所選び・持ち物／最後：「保存して当日見返してね」とサイトへの案内 |
| 記事紹介・スポット紹介 | X・Instagram | 記事のいちばん役に立つ1点＋方角・時刻・見え方 |
| 延期告知・結果・訂正 | X・Instagram | 7 章・8 章。**`approval: "owner"`** |

## 5. 画像（`imageBrief`）：図解だけ。写真風の絵は使わない
- 夜空の黒（#0B0B10）の地に白い線と文字、強調はオレンジ（#E8481C）**1か所だけ**。**AI で作った写真風の画像は使わない**（図・模式図だけ。「模式図」と分かるようにする。アイキャッチ用の写真風の背景は SNS に使わない）。
- 画像は必ず1枚以上。X は 1200×675、Instagram は 1080×1350（カルーセルは複数枚）。作るのは画像担当（`ops/sns_cards.py`）。`imageBrief` の形：
  ```json
  {"type": "week|direction|slide|poll", "format": "x|ig",
   "title": "大きな見出し（20字まで）", "sub": "副題", "range": "10/26〜11/1",
   "rows": [{"day": "27日（火）", "when": "夜", "text": "ISS が南西の空に4分間", "accent": true}],
   "center": 180, "points": [{"az": 225, "alt": 30, "label": "ISS", "accent": true}], "path": [[260, 8], [225, 30]],
   "lines": ["時刻：…", "方角：…"], "options": ["…", "…"],
   "slides": [{"type": "slide", "cover": true, "title": "…"}]}
  ```
  `week` は `rows`、`direction` は `points`（方位角 az・高さ alt は `sky.py` で出した値）、`slide` は `title`・`lines`、`poll` は `options`、カルーセルは `slides` に各枚の `type` つきで並べる。強調（`accent`・`accentLine`）は全体で1か所。
- 画像に入れる日時・数字は、本文と同じ**確かめた値だけ**。

## 6. 書き方の決まり
- **1行目に数字**（日付・時刻・方角）。コラム・豆知識は結論を先に。
- **X**：本文120字以内（URL を書かないので全部）。絵文字は1個まで。**ハッシュタグは1〜2個**（検索される名前に合わせる：#ふたご座流星群 #H3ロケット）。リンクは `replyText` に「https://…（記事名）」の形で書く。
- **Instagram**：キャプション300字以内、**ハッシュタグは1〜2個**、URL は書かない（「プロフィールのリンクから」）。
- 時刻は日本時間だけ。世界時からの変換と曜日は暗算せず `sky.py`（`weekday`）で出す。表記：日付「10月20日（火）」、時刻24時間制「4:41」、夜をまたぐとき「14日（月）の夜から15日（火）の明け方」。
- **見え方は正直に**：「暗い空での目安」と「街中での見え方」を分ける。見えにくいときは最初にそう書く。
- **使わない言葉**：「絶景」「一生に一度」「必見」「圧巻」「見逃し厳禁」、急かす言い方（「急いで」「売り切れ前に」）。
- 値段・在庫は書かない。**広告リンクを貼るときは「PR」と書く**（いまは貼らない）。
- 打ち上げの告知には、立入禁止・交通規制を守るひとことを入れる（文字数が許すとき）。
- エネルギー・原子力、政治・事故の論評は扱わない。

## 7. 情報源（根拠の順番）
1. 当事者（JAXA・スペースワン・インターステラテクノロジズ・各施設）→ 2. 自治体 → 3. 国立天文台 → 4. NASA・IMO → 5. 報道。まとめサイト・個人ブログ・SNS のうわさは根拠にしない。公式と報道が食い違うときは公式。確かめた URL を `sources` に書く。

## 8. 延期・変更が出たとき
公式ウォッチ（`watch`）が `events` を直したら（または依頼 `note` に「延期」）：①公式の発表を確かめる。②**予約済み・審査済みの、そのイベントに関係する投稿**を探し、直す下書きを作る（予約済みのものは書き換えない。`inbox/sns-<投稿ID>` に「止める必要がある（Metricool の予約を取り消す）」を `ownerOnly: true` で出す。Metricool の予約の取り消しはアプリのコネクタだけができるため）。③**延期告知**の下書き（新しい日時。未定なら「未定」。記事リンクはリプライ）を作る。`approval: "owner"`。目標は公式発表から30分以内に下書きまで。

## 9. 間違えたとき
投稿を黙って消さない。**訂正の投稿**（`kind: "訂正"`、`approval: "owner"`）の下書きを作る。別のブランドに出したことが分かったら、すぐ `inbox/sns-brand-wrong`（`ownerOnly: true`）。

## 10. やらないこと
KOAlil の ko ブランドへの投稿・予約／あおる言葉・見え方の誇張／いいね回り・フォロー返し狙いの行動／ほかの人の写真の無断転載／AI で作った写真風の画像／公式発表前の結果の投稿。

## 11. いつ動くか・手順
- 定時：**毎週土曜 9:43（来週分）**、と毎朝 8:43（直前の変化・当日分・延期の確認）。いまは `settings/agentPause` で止まっている場合がある（運営者がアプリで再開する）。依頼：`kind: "sns"`（`note` に「実況」「延期」などの指示）。
- **週の作業（土曜）**：
  1. サイト（予定まとめ・記事）と公式ページで、来週の打ち上げ・天体イベントを確かめる（`articles`（公開済み）・`events`・直近60日の `posts`）。
  2. ISS が見える時間・方角・月明かりを `sky.py` で計算する（東京の値。「東京での目安」と書く）。
  3. 来週の分を作る：見上げ予報（月曜 7:00）、前日リマインド、図解、紹介、Instagram の投稿。1日の量は X 2件まで・Instagram 1件まで。優先順位は 当日・前日 ＞ 予告 ＞ 記事の公開 ＞ 今夜の空 ＞ 豆知識。
  4. 6 章の決まりで書き、5 章の `imageBrief` を付ける。
  5. 予約前のチェック（下）を通す。
  6. `posts/<ID>` を `set`（下の形）。
  7. 審査に回す：作った投稿の ID を `note` に並べて `jobs/snsreview-<YYYYMMDDHHMM>`（`kind: "snsreview"`）を `queued` で書き、起動（`ops/agent-jobs.md` の 6）。
  8. 週の要約を受信箱に1件（運用開始から数週間のみ。`inbox/sns-week-<YYYYMMDD>`、`kind: "other"`、`body`：日時・媒体・本文・出典 URL の一覧）。
  9. 依頼を `done`、報告（3行以内）。
- **予約前のチェック**：□ 投稿先が miagetabi のブランド（`settings/sns.brandId` が 7372301 でない）□ 日時・方角を公式ページで確かめ出典 URL を控えた □ 時刻は日本時間で曜日を `sky.py` で確かめた □ 打ち上げの予定は、いま延期になっていない □ 1行目に数字・画像の指示がある・ハッシュタグは2個まで □ あおる言葉を使っていない。
- `posts/<ID>` の形（ID は 記事 `sns-<articleId>-<型>-<channel>`、イベント `sns-ev-<eventId>-<型>-<channel>`、予報 `sns-fc-<YYYYMMDD>-x`、図解・豆知識・投票 `sns-col-<YYYYMMDD>-<channel>`）：
  ```json
  {"date": "YYYY-MM-DD", "time": "07:00", "channel": "X|Instagram", "status": "下書き",
   "topic": "予報|記事|イベント|今夜の空|コラム|スポット", "kind": "見上げ予報|前日リマインド|参加型|図解|投票|引用|カルーセル|記事紹介|スポット紹介|延期告知|結果|訂正",
   "approval": "auto|owner", "text": "本文（X は URL なし）", "replyText": "（X のみ）自分のリプライ。https://… の記事名",
   "articleId": "", "eventId": "", "imageBrief": {"…5 章": ""}, "imageNote": "", "sources": ["確かめた公式URL"], "by": "sns", "createdAt": "<今>"}
  ```
- 差し戻し（`job.note` に「差し戻し」と投稿の ID）：`posts/<ID>.review.notes` の指摘だけを直し、`status` を `"下書き"` に戻して再審査。2回まで（3回目は審査が受信箱に出す）。

## 12. 月1回の報告（毎月1日）
型ごとに数字をまとめて受信箱に1件（`inbox/sns-month-<YYYYMM>`）：見上げ予報・前日リマインド・図解・カルーセル＝保存／参加型・投票＝リプライ・投票数／実況・引用＝インプレッション・リポスト／すべて＝プロフィールのアクセス・記事へのクリック。数字は Metricool のアナリティクス（コネクタが使えない実行環境では取れない）か、運営者が入れた値から。取れない項目は「未取得」と書く（作り話をしない）。フォロワー数より、**見上げ予報が保存・リポストされているか**を重く見て、伸びた型を増やす提案をする。
