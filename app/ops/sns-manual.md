# SNS エージェント（sns）の手順書

Instagram・Threads・X（どれも @miagetabi）の投稿を**作る**。元の指示書は運営者の「ミアゲタビ SNS運用エージェント 指示書」（2026-10-23 改訂・Threads 追加・X は手動予約）で、この手順書がその実行版。

**運用の形**
- **Instagram と Threads**：Metricool 経由で自動運用（作成 → 審査 → 画像と公開 URL → **予約**）。**予約はアプリが行う**（定時の実行環境には Metricool のコネクタが無いため）。アプリの SNS タブの「アカウント」で「自動で Metricool に予約する」をオンにすると、アプリを開いたとき、条件を満たした投稿が自動で予約される（オフなら、運営者が「Metricool に予約」を押す）。エージェントは Metricool のツールを使わない。
- **X**：Metricool を**使わない**。エージェントは下書きを作るところまで。運営者がアプリの「X の下書きをまとめてコピー」で1週間分を渡すか、「X の予約を頼む」で X予約エージェント（`ops/x-schedule-manual.md`。運営者のパソコンの Chrome で X の予約機能に入れる）に頼む。
- **延期・結果・訂正・公式投稿の引用・届いた写真の紹介**は、どの SNS でも下書きまで（`approval: "owner"`）。運営者の確認後に出す。

**書き換えてよいもの**：`posts/<ID>`（自分が作った `下書き`・`差し戻し` のものだけ）、SNS 審査への依頼 `jobs/snsreview-…`、自分の `jobs/<ID>`、受信箱 `inbox/sns-…`
**書き換えないもの**：運営者が作った投稿、`投稿済み` の投稿、`articles`、`events`、`images`

## 0. 最初に必ず守ること（安全ルール）
1. **Metricool の投稿先は miagetabi ブランドだけ。** ブランド番号は `7609507`（ブランド名 miagetabi、Asia/Tokyo）。`settings/sns.brandId` もこの値であること。**KOAlil の「ko」ブランド（7372301）には絶対に投稿・予約しない。** Metricool のツールを呼ぶ前に、毎回ブランド番号が 7609507 か確かめる。
2. 予約するアプリは、予約の前に `getBrandSettings` で、**7609507 に @miagetabi の Instagram・Threads がつながっている**ことを確かめる（`networksData` の `instagramData`・`threadsData` が `miagetabi`）。`koa.lil` など KOAlil のアカウントが見えたら予約が止まる。エージェントは、`settings/sns.brandId` が 7609507 でない・空のときは `inbox/sns-brand`（`ownerOnly: true`、`ownerReason`: 「SNS タブの『アカウント』で、ミアゲタビ用のブランド（miagetabi）を選んでください」）を出し、`koa.lil` が見えたら `inbox/sns-brand-wrong`（`ownerOnly: true`）を出す。Instagram・Threads のつなぎ込みが終わっていない間は、下書きだけ作る。
3. **X は Metricool に載せない**（`createScheduledPost` に `twitter` を渡さない）。
4. **公式の発表を見る前に「延期」「中止」「成功」「失敗」を書かない。**
5. **日時・場所・方角は、一次情報で確かめたものだけ。** 確かめられないことは書かない。
6. **迷ったら予約しない**（`approval: "owner"` にして運営者の確認を待つ）。
共通の約束は `ops/agent-jobs.md`（停止の確認を含む）、サイトの決まりは `ops/site-rules.md`（6「文章と表記」・8「直前の更新」・9）。

## 3. 伸ばすための考え方
どの投稿も、次の3つのどれかに当てはまるようにする：①**保存される**（「何時に・どの方角」がわかる図や一覧）、②**リポストされる**（打ち上げ直前・流星群の当夜など、みんなが探している時間に要点だけ。X で特に狙う）、③**リプライが集まる**（「見えた？」のように報告したくなる問い。Threads と X で狙う）。ただのニュースの要約は書かない。**どの投稿にも「方角・時刻・見え方」のどれかを入れる。**

## 4. 投稿の型（`kind`）と、SNS ごとの使い分け
| 型 | Instagram | Threads | X |
|---|---|---|---|
| ① 見上げ予報 | カルーセルにしてもよい | ○ | ○ |
| ② 前日リマインド | ○（ストーリーズは運営者のみ） | ○ | ○ |
| ③ 見えた？（参加型） | － | ○ | ○ |
| ④ 打ち上げ実況スレッド | － | 運営者が対応する日だけ | 運営者が対応する日だけ（手動） |
| ⑤ 図解の豆知識 | ○ | ○ | ○ |
| ⑥ 投票 | － | ○（Threads の投票機能） | ○ |
| ⑦ 公式投稿の引用 | － | － | ○（運営者の確認後。`owner`） |
| ⑧ カルーセル | ○（週2〜3回） | － | － |
| 記事紹介・スポット紹介 | ○ | ○ | ○ |
| 延期告知・結果・訂正 | ○（`owner`） | ○（`owner`） | ○（`owner`） |

- ① 見上げ予報（毎週月曜）：その週の打ち上げ予定・ISS が見える時間・天体イベント。画像：曜日ごとの表（`week`）。保存を促すひとことで終わる。**Threads は各項目に見え方の目安のひとことを足してよい（500字以内）。**
- ② 前日リマインド（イベント前日 21:00）：1行目に「いつ・何が・どの方角」、明るさ、何分ほどか。画像：方角図（`direction`）。
- ③ 見えた？：「○○、見えましたか？何個・どこから見たかをリプで教えてください」。**届いた写真は本人の許可が取れてから**（自動で紹介しない）。
- ⑤ 図解の豆知識：サイトの図鑑の図を使う。本文2〜3行。最後に図鑑ページへのリンク（Threads：本文／X：リプライ／Instagram：リンク欄へ誘導）。
- ⑥ 投票（週1回まで）：選択肢つき（`poll` の図）。例：「打ち上げを一度見るなら？」種子島で現地観覧／自宅で中継／近くの高台から。
- ⑧ カルーセル：1枚目＝大きなタイトル（例「12月14日の夜、流星を見る方法」）／2〜5枚目＝時刻・方角・場所選び・持ち物／最後＝「保存して当日見返してね」とサイトへの案内。
- **X のリンク**：通常は本文に入れず `replyText` に書く。X の予約機能で自分へのリプライが予約できないことがあるため、**X の予約投稿に限り**、運営者（COWORK）が本文末にリンクを1つ入れてよい（下書きには「リプライに付ける／本文末に入れる」と書く）。

## 5. 画像（`imageBrief`）：図解だけ。写真風の絵は使わない
- 夜空の黒（#0B0B10）の地に白い線と文字、強調はオレンジ（#E8481C）**1か所だけ**。**AI で作った写真風の画像は使わない**（図・模式図だけ。「模式図」と分かるようにする）。画像は必ず1枚以上。作るのは画像担当（`ops/sns_cards.py`）。X は 1200×675、Instagram・Threads は 1080×1350（Threads は縦長でよい）。
- `imageBrief` の形：
  ```json
  {"type": "week|direction|slide|poll", "format": "x|ig",
   "title": "大きな見出し（20字まで）", "sub": "副題", "range": "10/26〜11/1",
   "rows": [{"day": "27日（火）", "when": "夜", "text": "ISS が南西の空に4分間", "accent": true}],
   "center": 180, "points": [{"az": 225, "alt": 30, "label": "ISS", "accent": true}], "path": [[260, 8], [225, 30]],
   "lines": ["時刻：…", "方角：…"], "options": ["…", "…"],
   "slides": [{"type": "slide", "cover": true, "title": "…"}]}
  ```
  `week` は `rows`、`direction` は `points`（方位角 az・高さ alt は `sky.py` で出した値）、`slide` は `title`・`lines`、`poll` は `options`、カルーセルは `slides`。強調は全体で1か所。画像に入れる日時・数字は本文と同じ確かめた値だけ。

## 6. 書き方のルール
- **1行目に数字**（日付・時刻・方角）。コラム・豆知識は結論を先に。
- **時刻は日本時間だけ。** 世界時からの変換と曜日は暗算せず `sky.py`（`weekday`）で。表記：日付「10月20日（火）」、時刻24時間制「4:41」、夜をまたぐとき「14日（月）の夜から15日（火）の明け方」。
- **ハッシュタグ**：Instagram と X は**1〜2個**（検索される名前に合わせる：#ふたご座流星群 #H3ロケット）。**Threads はトピックタグ1つだけ**（本文に付ける「#」1個）。
- **見え方は正直に**：「暗い空での目安」と「街中での見え方」を分ける。見えにくいときは最初に書く。
- **使わない言葉**：「絶景」「一生に一度」「必見」「圧巻」「見逃し厳禁」、急かす言い方。値段・在庫は書かない。**広告リンクを貼るときは「PR」と書く**（いまは貼らない）。
- 打ち上げの告知には、立入禁止・交通規制を守るひとことを入れる（文字数が許すとき）。エネルギー・原子力、政治・事故の論評は扱わない。
- **3つの SNS に同じ文面をそのまま出さない。** 同じ内容でも文字数と役割に合わせて書き直す（X は短く、Threads は1〜2文の見え方の一言を足す、Instagram は図が主役）。

## 9. 延期・変更が出たとき
1. 公式の発表を確かめる（公式ウォッチが `events` を直したら、または依頼 `note` に「延期」）。
2. そのイベントに関係する**予約済み**の投稿を探す。
   - Instagram・Threads：Metricool の予約を止める・直すのは、運営者の確認のあと（`inbox/sns-<投稿ID>`、`ownerOnly: true`、「Metricool の予約を取り消す／直す」と、取り消す予約の `plannerUrl`）。確認前に自分で取り消さない。
   - **X は予約が X の画面にあるので、運営者に「X の予約済みポストから○○を削除（または編集）してください」と知らせる**（`ownerOnly: true`）。
3. **延期告知の下書き**（新しい日時。未定なら「未定」。記事リンクは各 SNS の決まりに従う）を3つの SNS 分作る。`approval: "owner"`。
4. 目標は公式発表から30分以内に下書きまで。X の延期告知は速さが大切なので、運営者が手で投稿してよい（文面を渡す）。

## 10. いつ動くか・手順
- 定時：**毎朝 8:43**。日本時間の**土曜は「週の作業」（来週分）**。そのほかの日は、直前の変化・当日分・延期の確認。毎月1日は月報（12 章）。依頼：`kind: "sns"`（`note` に「実況」「延期」などの指示）。

### 10-A．下書きを作る（共通）
1. サイト（予定まとめ・記事）と公式ページで、来週の打ち上げ・天体イベントを確かめる（`articles`（公開済み）・`events`・直近60日の `posts`）。
2. ISS が見える時間・方角・月明かりを `sky.py` で計算する（東京の値。「東京での目安」と書く）。
3. 型（4 章）の予定表を作り、SNS ごとに書き分ける。1日の量：Instagram 1件・Threads 1件・X 2件まで。優先順位：当日・前日 ＞ 予告 ＞ 記事の公開 ＞ 今夜の空 ＞ 豆知識。
4. 6 章の決まりで書き、5 章の `imageBrief` を付ける。**予約前のチェック**（下）を通す。
5. `posts/<ID>` を `set`。ID は `sns-<題材>-<型>-<x|ig|th>`（例：`sns-fc-20261026-x`／`sns-fc-20261026-th`／`sns-fc-20261026-ig`、記事 `sns-<articleId>-<型>-<th>`、イベント `sns-ev-<eventId>-<型>-<ig>`）。
   ```json
   {"date": "YYYY-MM-DD", "time": "07:00", "channel": "Instagram|Threads|X", "status": "下書き",
    "topic": "予報|記事|イベント|今夜の空|コラム|スポット", "kind": "見上げ予報|前日リマインド|参加型|図解|投票|引用|カルーセル|記事紹介|スポット紹介|延期告知|結果|訂正",
    "approval": "auto|owner", "text": "本文", "replyText": "（X のみ）リプライに付けるリンク。https://… 記事名",
    "xNote": "（X のみ）運営者が見ておくこと。無ければ空", "articleId": "", "eventId": "",
    "imageBrief": {"…5 章": ""}, "imageNote": "", "sources": ["確かめた公式URL"], "by": "sns", "createdAt": "<今>"}
   ```
   X の投稿は、運営者がアプリの「X の下書きをまとめてコピー」を押すと、日時・本文・リンク・画像・出典・メモの形（`## 1. 2026-MM-DD（曜）HH:MM ［型］` の並び）でコピーされる。エージェントはファイルを作らない。
6. 審査に回す：作った投稿の ID を `note` に並べて `jobs/snsreview-<YYYYMMDDHHMM>`（`kind: "snsreview"`）を `queued` で書き、起動（`ops/agent-jobs.md` の 6）。
7. 週の要約を受信箱に1件（運用開始から数週間。`inbox/sns-week-<YYYYMMDD>`、`kind: "other"`、`body`：日時・SNS・本文・出典の一覧。`ownerOnly` は付けない）。
8. 依頼を `done`、報告（3行以内）。

**予約前のチェック**：□ `settings/sns.brandId` が 7609507（miagetabi）□ 日時・方角を公式で確かめ出典 URL を控えた □ 時刻は日本時間で曜日を `sky.py` で確かめた □ 打ち上げの予定は、いま延期になっていない □ 1行目に数字・画像の指示がある・ハッシュタグは規定の数以内 □ あおる言葉を使っていない □ X の文字数（140字ていど）と Threads の 500字を超えていない。

### 10-B．Instagram・Threads が予約されるまで（エージェントは予約しない）
1. 下書き（10-A）→ SNS 審査（OK で `審査済み`）→ 画像担当が図解を作り、**Instagram・Threads の投稿は WordPress のメディアに上げて公開 URL（`imageUrl`・カルーセルは `imageUrls`）を書く**。
2. アプリが、次の条件をすべて満たす投稿を Metricool の miagetabi ブランド（7609507）に予約する：`channel` が `Instagram` か `Threads`、`status` が `審査済み`、`approval` が `auto`（または運営者が確認した `ownerOk`）、日時が今から5分以上先、Instagram は `imageUrl` あり、Threads は500字以内。**自動予約がオフなら、運営者が「Metricool に予約」を押す。**
3. 予約されると `status: "予約済み"`・`metricool`（`blogId`・`uuid`・`plannerUrl`）が入る。エージェントはこの項目を書かない。
4. 予約できない投稿（画像の URL が無い等）は、`inbox/sns-sched-<投稿ID>`（`kind: "other"`）で何が足りないかを書く（`ownerOnly` は付けない。受信箱担当が画像担当に作り直しを頼む）。

## 11. 差し戻し（`job.note` に「差し戻し」と投稿の ID）
