# ミアゲタビのサイトの決まり（エージェント用の抜き書き）

運営者の「ミアゲタビ サイト運営マニュアル」（https://claude.ai/artifact/PvUNQhB5LZbex2JmDaS1zE ）から、エージェントが書く・確かめる・提案するときに必要な決まりだけを抜き出したもの。**マニュアルと食い違ったらマニュアルが正しい。** マニュアルが変わったら、このファイルを直す（運営者がアプリ開発のセッションに頼む）。

---

## 1. サイトの目的と約束

- 目的：ロケットの打ち上げ、天体イベント、宇宙スポットを、初めての人でも「いつ・どこへ・何を持って」行けばいいかわかるように案内する。「知って終わり」ではなく「見に行ける」記事だけを書く。
- 読者：宇宙に興味はあるが詳しくない人。初めて打ち上げを見に行く人、子どもと流星群を見たい家族。現地へ行く人と、家の近くの空や中継で見る人の**両方**に答えを出す。中学生が読んでわかる言葉で書く。
- 守る3つの約束（トップページにも書いてある）
  1. 日時・場所・料金は、公式の発表を見てから書く。確かめられないことは「推測」と書く。
  2. すべての記事に「最終確認日時」を出す。
  3. 延期などの変更は、発表から30分以内の更新を目指す。
- AI の下書きはそのまま公開しない。日時・場所・料金・予約の要否は、運営者が公式ページを開いて目で確かめてから公開する。

## 2. 扱うこと・扱わないこと

| 区分 | 中身 |
|---|---|
| 扱う | 国内のロケット打ち上げ観覧（種子島・内之浦・紀伊・大樹）／日本から見える天体イベント／見学できる宇宙施設と星空スポット／見に行くための持ち物・宿・交通 |
| 条件つき | 海外の打ち上げや日食：日本から見に行く人がいるもの、中継で見られるものだけ。宇宙ニュース：「見られる」「行ける」につながるときだけ |
| 扱わない | 宇宙ビジネス・投資の話、政治的な論評、**エネルギー・原子力の話題**、UFO・占星術などの疑似科学、事故をあおる記事 |

### 記事にするかどうかの3つの問い（3つとも Yes のときだけ書く）
1. 読者が「見る」「見に行く」ために使えるか。
2. 公式の一次情報で確かめられるか。
3. ほかのサイトにない要素（計算した方角や時刻、当日のタイムライン、延期のときの動き方、見学場の比較など）を2つ以上入れられるか。

1つでも No なら、常設ガイドの中の一節にするか、書かない。

## 3. 情報源と「推測」

- 根拠の順番：当事者（JAXA・スペースワン・インターステラテクノロジズ・各施設）→ 自治体 → 国立天文台 → NASA・IMO → 報道。まとめサイト、個人ブログ、SNS のうわさは根拠にしない。
- 時刻は日本時間だけで書く。世界時からの変換と曜日は、暗算せずコード（`ops/sky.py`）で出す。
- **確かめられないことは書かない。** どうしても必要な見込みだけ「推測」と書き、理由を添える（例：「推測：前回の10号機では満車が5時ごろだったため（南種子町の発表）」）。「要確認」と書いて残すのは不可。
- 「編集部の目安」（何時までに着くか等）は、確かめた事実から導いた理由と一緒にだけ書く。
- 公式の発表と報道が食い違うときは、公式のほうを書き、食い違いがあることにも触れる。

## 4. カテゴリ・タグ・URL

記事はカテゴリ1つ＋決まったタグで整理する。カードの `pillar` がカテゴリのスラッグ。

| カテゴリ | スラッグ（`pillar`） | 入れる記事 |
|---|---|---|
| 打ち上げを見る | `launch` | 打ち上げ予定、見学場所・観覧ガイド、中継、打ち上げ結果。射場へ行く旅のガイドもここ |
| 星空を見る | `sky` | 流星群・日食・月食・惑星・ISS などの天体イベントと、星空の撮り方 |
| 宇宙を訪ねる | `spot` | 科学館・プラネタリウム・JAXA の施設・星空の名所など、打ち上げがない日でも行く価値がある場所 |
| 機材・持ち物 | `gear` | 双眼鏡・三脚・防寒具などの選び方。アフィリエイトの中心 |
| お知らせ | `news` | サイトの更新・運営からの連絡（エージェントは書かない） |

迷ったら「読者がこの記事を読んで、何をしに行くか」で決める。新しいカテゴリ・子カテゴリは作らない。

**タグ（決まった名前だけ。無いものを作らない。必要なら運営者に受信箱で提案する）**

| 種類 | タグ（スラッグ） |
|---|---|
| 機体 | H3（h3）、H-IIA（h-iia）、イプシロンS（epsilon-s）、カイロス（kairos）、ZERO（zero） |
| 場所 | 種子島（tanegashima）、内之浦（uchinoura）、串本（kushimoto）、大樹町（taiki） |
| テーマ | 流星群（meteor-shower）、撮影（photography） |

**URL**：英小文字とハイフン、2階層まで。記事は `/launch/記事名/` の形。
- 毎年くり返すイベント：年を入れない（`/sky/geminids/`）。タイトルには年を入れて毎年書き換える。
- 1回きりの打ち上げ：号機を入れる（`/launch/h3-f10-mmx/`）。

**資料ページ（固定ページ。記事ではない）**：ロケット図鑑 `/rockets/`（`/rockets/h3/` ほか各機体）、年表 `/history/`。打ち上げの記事からは、出てくる機体の図鑑ページへ必ずリンクする。

## 5. 記事の型（部品の並び）

本文は Markdown で書き、サイトの部品は `:::` で囲む（`ops/md2blocks.py` が WordPress のブロックに変える）。

| 部品 | 書き方 | 決まり |
|---|---|---|
| 要点ボックス（mg-info） | `:::info 英字の見出し`〜`:::`。中は「項目: 値」を1行ずつ。「今の状況」の値の頭に `[go]`（予定どおり）`[delay]`（延期）`[stop]`（中止）`[sky]`（天体）`[open]`（開館）`[done]`（終了） | 記事の冒頭に1つだけ |
| 最終確認の一行（mg-verified） | `最終確認：YYYY-MM-DD H:MM（出典：〇〇）` | 要点ボックスの直後 |
| 強調（mg-point） | `:::point 見出し`〜`:::` | 注意・安全・大事な条件。1記事に2つまで |
| 表 | Markdown の表 | 3列まで |
| よくある質問 | `## よくある質問` の下に `### 質問` と答え | 1問1答を短く。3〜4組 |
| 出典（mg-src） | `:::src`〜`:::`。「- 名前：URL」を1行ずつ | 記事の最後。公式を先に並べる |
| 更新履歴（mg-history） | `:::history`〜`:::`。「- YYYY-MM-DD　何をしたか」 | 出典の後 |

図（mg-fig）・ボタン・SWELL のステップは運営者が入れる。エージェントは `report` の「図の案」に書く（方角図・見学場の位置図・タイムライン図。数字は sky.py の値）。

### 打ち上げ観覧
要点ボックス（今の状況・日時・場所・予備期間・見る方法の要点）→ 最終確認 → 導入2〜3文 → `## まず結論`（読者のタイプ別におすすめの見方を3つまで）→ 基本情報 → 見る場所 → 当日の動き方 → 行き方 → 延期のとき → よくある質問 → 出典 → 更新履歴

### 天体イベント
要点ボックス（いつ〈夜をまたぐときは2つの日付〉・方角と高さ・どのくらい見えるか〈暗い空の目安と街中を分ける〉・月明かり・天気の確認先）→ 最終確認 → 導入 → `## まず結論`（今年の見やすさを1段落で）→ 時刻表 → 主な都市での方角と高さ → 場所選び → スマホでの撮り方 → 持ち物と寒さ対策 → 曇ったとき・見逃したとき → よくある質問 → 出典 → 更新履歴

### 宇宙スポット
要点ボックス（どこ〈都道府県・最寄り駅〉・予約が要るか・料金・何時間あれば楽しめるか）→ 最終確認 → どんな場所か → 見どころ（3つまで）→ 予約と当日の流れ → 訪問レポート → 行き方 → あわせて行きたい場所 → 休館・変更の確かめ方 → よくある質問 → 出典 → 更新履歴
- 訪問レポートは運営者が実際に行ったときだけ。行っていなければ公式情報だけで書き、「訪問レポートは準備中」と明記する。

### 機材・持ち物
要点ボックス（結論〈この場面ならこれ〉と選ぶ基準3つ）→ どの場面で要るか → 選ぶ基準 → 候補（3つまで。合う人・合わない人）→ 使い方のコツ → よくある質問 → 出典 → 更新履歴
- 値段は書かない。使っていない物を「使ってみた」と書かない。

## 6. 文章と表記

- 落ち着いた案内役として書く。あおらない、盛らない。「絶景」「一生に一度」「圧巻」「最強」「必見」は使わない。読者を急かさない。
- 見え方は正直に。「暗い空での目安」と「街中での見え方」を分け、見えにくいときは最初にそう書く。
- 結論を先に。各見出しの最初の1〜2文で答える。1文は短く。専門用語は言い換える（「フェアリング＝衛星を包む先端のカバー」）。
- 数字には単位と出典。「約」「ごろ」は公表値がおおよそのときだけ。
- **同じページの中で、同じ数字を2回書かない**（直すときに片方が古くなる）。要点ボックスに出した数字は、本文では言い換えるか参照にとどめる。
- 文字だけの画面が3スクロール以上続かないよう、「見出し → 文章2〜3段落 → 表・箇条書き」をくり返す。1段落は3〜4行まで。太字は1段落に1か所まで。

| 項目 | 書き方 | 書かない例 |
|---|---|---|
| 日付 | 10月20日（火）。年がまたがるときは2026年10月20日（火） | 10/20、20日（火曜日） |
| 時刻 | 24時間制で4時41分。表と要点ボックスは4:41 | 午前4時41分、AM4:41 |
| 夜をまたぐ時間 | 14日（月）の夜から15日（火）の明け方 | 15日未明 |
| 時刻の基準 | 日本時間だけ。JST は英字ラベルの中だけ | 世界時（UT）のまま |
| 数字 | 半角。4けた以上はカンマ（2,000人） | 全角の数字 |
| ロケット名 | H3ロケット10号機。2回目からはH3 10号機 | H3-10、H-3 |
| 打ち上げ | 「打ち上げ」で統一。公式名に「打上げ」とあるときだけそのまま | 発射（射点・発射台は可） |
| 方角 | 南東の空、高さ30度くらい | 右のほう、上のほう |
| 施設名 | 1回目は正式名。2回目から略してよい | いきなり略称 |

## 7. タイトル・説明文・内部リンク

- タイトルは32字前後。読者が検索する言葉（イベント名・号機・場所）を前に、記事が答える問い（いつ・どこで・何時）を入れる。例：「H3ロケット10号機はいつ？ 種子島で見る場所と時間」
- 曜日は3日前の更新から入れる。「今夜」「明日」は前日と当日だけで、過ぎたら外す。
- 説明文は80〜120字。誰に向けた記事か、何がわかるか、最終確認日を入れる。
- 内部リンク：機体名は図鑑（`/rockets/…`）へ、射場名は見学ガイド（`/launch/tanegashima/` など）へ、撮り方は `/sky/smartphone/` へ。「まず結論」までの中に、いちばん関係の深い常設ガイドへのリンクを1本。リンクの文字は「こちら」にせず、行き先がわかる言葉に。リンクしてよいのは、公開済み（`articles` の `status` が `"公開済み"`）の記事と資料ページだけ。
- 終わったイベントの記事は、冒頭から次の回の記事へリンクする。

## 8. 公開と更新のタイミング

| 記事の種類 | 初回公開 |
|---|---|
| 流星群・満月などの天体イベント | イベントの30日前 |
| ロケット打ち上げ（日時が発表されたもの） | 発表から48時間以内 |
| ロケット打ち上げ（日時未発表） | 「打ち上げ予定まとめ」や図鑑ページの中に書いておき、発表後に記事を切り出す |
| 宇宙スポット・常設ガイド | 随時 |

直前の更新（検索はイベント当日〜3日前に集中する）
- 7日前：天気の傾向、宿の空き、交通の注意を追記。SNS で告知。
- 3日前：公式情報をもう一度確認。タイトルに曜日を入れる。
- 前日：天気予報を反映。延期の発表があればすぐ直す。
- 当日：要点ボックスの「今の状況」を更新。中継のリンクを上へ。
- 翌日：結果を追記し、次のチャンスへのリンクを冒頭に。

延期が発表されたら（30分以内）運営者がすること：要点ボックスの「今の状況」を `[delay]` にし新しい日時（未定なら「未定」）／最終確認の日時と更新履歴を1行足す／ホームのカウントダウン（スクリプトの打ち上げ一覧を書き換える。下の「ホームのカウントダウン」）・表紙カード・ティッカー・UPCOMING の表（同じ内容が2回ずつ）／図鑑ページの「NEXT」と「打ち上げ予定まとめ」の表／X で告知。

訂正：事実の誤りは更新履歴に「訂正：何を、何に直したか」を残す。日時・場所・安全にかかわる大きな誤りは冒頭に訂正の一文を7日間。修正の理由を本文の地の文に書かない（履歴だけ）。終わったイベントの記事は消さない。

## 9. 体験・写真・お金

- 行っていない・見ていないことを、体験したように書かない。体験談は運営者が実際に行ったときだけ、その日付を添えて。
- 写真は運営者が撮ったものか、利用規約で使える公式の画像だけ。AI で作った写真風の画像は使わない。図には「模式図」「簡略化」と書く。
- アフィリエイトは、その場面で本当に必要なもの（宿・交通・三脚・防寒具）だけを、必要な理由と一緒に。広告の有無で評価や順番を変えない。値段・在庫・ポイントは書かない。広告表記は SWELL の設定で全記事に出る（広告リンクの無い記事は運営者が個別にオフにする）。
- 安全：立入禁止区域・私有地・交通規制を守る前提で書く。夜道・寒さ・車の運転の注意は当てはまる記事に必ず。日食は太陽を直接見ない注意を冒頭に。射場まわりでドローンを勧めない。

## 10. ロゴと色（ミアゲタビ ロゴガイド）

- 色：INK `#111111`（ロゴ・本文・罫線）／SIGNAL ORANGE `#E8481C`（星と発射台だけに使う差し色）／PAPER `#FFFFFF`・`#F4F3EF`（背景）。
- 書体：英字 Archivo ExtraBold、日本語 Noto Sans JP Bold。
- ロゴの形：地平線から空を見上げる弧と、その先の星（オレンジの丸）。地平線は英字の下線になり、右端のオレンジの区切りが発射台。
- 使い方：まわりに星の直径の2倍以上の余白。オレンジは星と発射台の2か所だけ。縦横比を変えない・傾けない・影や縁取りを付けない。写真の上では白抜き版を暗い部分に。
- エージェントはロゴを描かない・作り直さない。SNS やアイキャッチの案で「ロゴを入れる」ときは、運営者が持っているロゴのファイルを使う前提で、置き場所だけを書く。

## 11. 記事の状態（アプリの記事ボード）

企画中 → 執筆中 → 査読中 →（差し戻しで執筆中へ）→ 公開待ち（査読 A・アイキャッチ待ち。できたら入稿エージェントが自動で WordPress に反映）→ 公開済み → 要更新（公式の発表が変わった・見直し時期が来た）
- 企画中のカードは企画エージェントが作り（優先度つき）、記事選定エージェントが査定して、期間と本数に合わせて執筆中に回す。運営者が手で執筆中に移したものも、記事作成が自動運転なら書き始める。査定で落ちたものは `保留`（受信箱で運営者が判断）、見送ったものは `見送り`。

## 12. ホームのカウントダウン（自動で次の打ち上げに切り替わる）
- トップページの「NEXT LAUNCH」は、ページの `<script>` の中に**打ち上げの一覧**を持ち、見た人の時計で、いちばん近い打ち上げに自動で切り替わる。予定時刻から6時間たつと次の打ち上げへ。日付が決まった打ち上げが無いときは、「日程の発表待ち」と、近そうな打ち上げの名前（と時期）を出す。
- 一覧の書き換えは、**サイト更新エージェント**（`ops/site-manual.md`）が自動で行う（日程が変わったとき・毎朝）。WordPress に書き込めない場合は、受信箱に貼り替え用の差分が出るので、運営者が WordPress のトップページの `<script>`（`id="mgCount"` を使っているもの）を丸ごと入れ替える。
- 作り方：`ops/home_countdown.py`（Artifact ツールで読み、保存先のまま `python3` で実行）に、`events` の打ち上げ（`pillar: "launch"`）を JSON にして渡す。`python3 home_countdown.py launches.json > countdown-script.html`。各項目は `title`・`sub`（場所と一言）・`date`・`time`・`dateText`・`status`・`guide`（図鑑ページの URL）・`guideLabel`・`official`（公式ページ。報道だけなら空）・`publicNote`（読者に見せる一文。**内部のメモは入れない**）・`rank`（日付が無いものの順番）。`status` が `確定`・`予定`・`延期` のものだけが入る。
- 公式ウォッチ・イベント取得は、打ち上げ・天体の日付・状況を変えたら、サイト更新に依頼を出す（`jobs/siteupdate-<YYYYMMDDHHMM>`）。ティッカー・UPCOMING の表も同じ仕組みで直る。
