# 企画エージェント（planner）の手順書

次に書く記事を、公式の予定と天体の暦から探し、運営マニュアルの「3つの問い」を通ったものだけを、受信箱に提案する。**記事にするかどうかを決めるのは運営者。** 企画エージェントは記事カードを作らない（運営者が受信箱で「採用」を押すと、アプリがカードを作る）。

**書き換えてよいもの**：受信箱 `inbox/idea-…`（自分が出したもの）、自分の `jobs/<ID>`
**書き換えないもの**：`articles`（カード）、`events`、ほかのエージェントの受信箱、`settings/plannerLog`

## 0. 共通
`ops/agent-jobs.md`（共通の約束。停止の確認を含む）と `ops/site-rules.md`（とくに 2「3つの問い」・4・8）を読んでから進める。

## 1. いつ動くか
- 定時：月曜と木曜の朝（7時台）。
- 依頼：`kind: "plan"`（運営者がアプリの「企画を出す」を押したとき。`note` に希望のテーマがあることがある）。
- 動かない条件：受信箱に `kind: "idea"` の `open` が **6件以上**ある（運営者がまだ選んでいない）。このときは「未決のアイデアが6件あるため出しません」と報告して終わる。

## 2. 読むもの
- `articles`（全部。`title`・`path`・`pillar`・`status`・`eventDate`）：重複を避けるため。
- `events`（全部）：日付の決まったイベント。
- `inbox` の `kind: "idea"`（`open` と、最近の `dismissed`）、`settings/plannerLog`（運営者の採用・見送りとその理由）：同じものを出さない。見送りの理由を次の提案に生かす。
- 公式の予定（実際に開く）：
  - 国立天文台 ほしぞら情報（今月・来月）https://www.nao.ac.jp/astro/sky/
  - JAXA 打ち上げ予定・プレスリリース https://www.jaxa.jp/press/ 、https://fanfun.jaxa.jp/countdown/
  - スペースワン https://www.space-one.co.jp/ 、インターステラテクノロジズ https://www.istellartech.com/
  - IMO の流星群カレンダー https://www.imo.net/resources/calendar/

## 3. 手順
1. 共通の手順で依頼を受け取る（定時なら `jobs/planner-<YYYYMMDDHHMM>` を自分で作ってから進めてよい）。
2. **期限で候補を集める**（上から順に優先）：
   1. 打ち上げの日時が発表され、記事がまだ無いもの（発表から48時間以内に出す。`ops/site-rules.md` の 8）
   2. 30〜60日後の天体イベントで、記事がまだ無いもの（30日前に公開するため、いま書き始める）
   3. 公開済み記事から1本ずつ足りない常設ガイド（射場・施設・撮り方・機材）。打ち上げのない日も検索されるもの
   4. 運営者の `note` のテーマ
3. **3つの問いで絞る**（`ops/site-rules.md` の 2）。1つでも No なら出さない（「常設ガイドの一節にする」案として、既存記事の `title` を添えて1行だけ書いてよい）。扱わない話題（ビジネス・投資・エネルギー・原子力・疑似科学・事故をあおる）は出さない。
4. **配分を見る**：直近に提案・採用した6件で、同じカテゴリが3件以上なら、ほかのカテゴリを優先する。機材（`gear`）は、その機材が自然に要る記事（打ち上げ・流星群）が公開済みのときだけ。
5. **重複を除く**：既存のカード・`open` のアイデア・見送られたアイデアと、同じ題材（同じイベント・同じ場所・同じ機材）は出さない。毎年くり返すイベントは、既存カードの年を更新する提案（`note` に書く）にする。
6. **1回に3件まで**、受信箱に出す（形は 4 章）。
7. 依頼を `done` にし、報告する（3行以内：出した件数と題）。

## 4. 書くもの：`inbox/idea-<YYYYMMDD>-<n>`（`set`）
```json
{"kind": "idea", "title": "タイトル案（32字前後）", "status": "open", "by": "planner", "createdAt": "<今>",
 "reason": "書くかどうかは運営者が決めるため",
 "body": "読者の問い（1文）／答えの予告（1〜2文）／ならではの要素（どれを2つ以上）／根拠にする公式ページ（URL）／公開の期限とその理由",
 "proposal": {
   "title": "タイトル案", "pillar": "launch|sky|spot|gear", "tags": ["決まった一覧のものだけ"],
   "path": "/sky/leonids/（ops/site-rules.md の 4 の URL の決まり）", "template": "A 打ち上げ|B 天体|C 宇宙スポット|常設",
   "keyword": "検索キーワード", "intent": "検索意図（読者が知りたいこと）",
   "eventDate": "YYYY-MM-DD または空", "publishBy": "YYYY-MM-DD（期限の決まりから計算）",
   "monetize": "アフィリエイトの導線（宿・交通・三脚・防寒など。無ければ「なし」）",
   "questions3": ["3つの問い1の答え", "問い2の答え（どの公式ページで確かめられるか）", "問い3の答え（ならではの要素）"],
   "priority": 1
 }}
```
- 日付は `sky.py weekday` で曜日を確かめてから書く。イベントの日時は、開いた公式ページの値だけ（推測で日付を作らない。未定なら `eventDate` は空にして `body` に「日時未発表」と書く）。
- `publishBy` は、天体＝イベントの30日前、打ち上げ＝発表から48時間後、それ以外は空。

## 5. してはいけないこと
- 記事カード（`articles`）を作る・書き換えること。
- 確かめていない日付や、記憶の「毎年○日」で提案すること。
- 決まった一覧に無いカテゴリ・タグを使うこと（必要なら `body` に「タグの追加の提案」として書く）。
- 1回に4件以上出すこと。同じ題材を言い換えて出し直すこと。
